# Notice

Cardigan (a Chrome extension, called Anaplan Analyzer up to version 0.6.0) is an independent project. It is **not affiliated with, endorsed by or supported by Anaplan, Inc.** "Anaplan" is used only to say which service the extension reads.

- **Internal services.** The extension reads Anaplan's internal page services: the page and app definition service, Page Builder's model data socket, the actions service, and the classic Model Building client inside the page. A model's settings are read through that client; after them, the pages built on the model are read as an app's are: Model Building's list of those pages and each page from the definition service, the name of each of their apps, and the names their cards use from the model data socket and the actions service. These are not public, documented APIs. Anaplan can change them without notice, and the extension can then stop working or show incomplete results.
- **Read-only by construction.** REST reads are GET-only and limited to the services it reads. Apart from opening and closing its connection, the socket client refuses to send anything except subscribe, unsubscribe and `update-subscription` frames. When a model is read, every request is checked to carry no changes before it is sent. That holds for each import's saved mapping too, which is read from the import's own definition as Anaplan's import dialog reads it: the extension never saves a definition, and never asks Anaplan for a file's columns, a request that can store what it is given. Tests pin each of these rules.
- **Only when you ask.** The extension adds nothing to Anaplan's pages: no button and no panel. Nothing is read from Anaplan until you click the extension's icon in Chrome's toolbar. The results page that opens then starts the read. It reads again only when you choose **Run again**. A results page that is reloaded, duplicated, restored from history or reopened later reads nothing by itself: it shows the result its tab kept, if it kept one (see below), and waits for you to choose **Run again**, or **Run** when it has no result. Closing the results page stops the read. Clicking the icon on an Anaplan tab whose Cardigan script is gone, as after Cardigan was installed, updated or reloaded, puts the script back into that tab first (the **activeTab** and **scripting** permissions, neither with a warning): it reaches no other tab and no other site, and reads nothing until the results page asks. The buttons at the top right of a row's details, in a model's result, take that same Anaplan tab to the row's module in Model Building, or to an app or a page built on the model, and bring it to the front. If that tab has been closed, the first of them opens one tab in its place, and the others then use it. Cardigan changes which page the tab shows, and nothing in the model or the app.
- **Reading can load a model.** Reading a model's names, for an app or for the pages built on a model, subscribes to that model, which can make Anaplan load it, as opening one of its pages would.
- **Two choices are kept.** The theme you chose with the sun or moon button, and how you chose to group the Model map's modules, are kept in the browser's local storage for the extension, so that the next results page opens with them. Each is one word, such as dark or role, and holds nothing of your app or model. They stay until the extension's storage is cleared.
- **Nothing leaves the browser** except those reads to Anaplan, made with your own signed-in session. The results page is part of the extension and loads nothing from the internet: the extension's content security policy lets its pages and its service worker load only files from its own package, and the packager refuses a policy that would allow more, or a manifest that declares none. The extension makes no file and offers no download: a result is shown on the results page and nowhere else, apart from the copy kept for a refresh (see below). There is no server, analytics or telemetry.
- **The model map is drawn in your browser.** It is made from the tables of a model's result and from nothing else: opening it reads nothing more from Anaplan and sends nothing anywhere.
- **The last result is kept for a refresh.** So that refreshing the results page does not lose it, the last result that finished in a results tab is kept in the browser's session storage for that tab. It is compressed with gzip and not encrypted, and it is kept with the time it was complete, the Anaplan tab's ID and the extension's version. A model's result read in Model Building holds where it was read as well: the site and the customer ID that tab's address named, by which the buttons in a row's details open its modules, apps and pages. It holds what the page shows: the details of your app or model. That storage is the extension's own, apart from every website's, and using it takes no permission. The result is not sent anywhere. The next result that finishes in that tab takes its place, and **Forget this result** on the Overview removes that tab's copy at once: the result stays on the page until the page is refreshed or closed, and a refresh then finds nothing kept. If the browser refuses the removal, the page says that the copy could not be removed and keeps the control, so that it can be tried again. A refreshed page shows only what its own version of the extension kept for the Anaplan tab named in its address. Anything else it finds there, and a kept value it cannot show, it removes, and then it waits for **Run**. Session storage is meant to go when its tab is closed, but that is the browser's to do, not the extension's: the browser may hold a closed tab's session data for a while, so that the tab can be reopened or a window restored, and a duplicated tab gets a copy. So closing the tab is no promise that the result is erased. A result too large to keep is not kept at all, and the page says so.
