# Notice

Cardigan (a Chrome extension, called Anaplan Analyzer up to version 0.6.0) is an independent project. It is **not affiliated with, endorsed by or supported by Anaplan, Inc.** "Anaplan" is used only to say which service the extension reads.

- **Internal services.** Cardigan reads Anaplan's page and app definitions, model data socket, action listings, platform-gateway names for reads without a client, Polaris metadata, and the Classic Model Building client's settings grids. [Requests to Anaplan](#requests-to-anaplan) below lists the routes and reads. These are internal services, not public, documented APIs. Anaplan can change them without notice, and Cardigan can then stop working or show incomplete results.
- **Read-only by construction.** REST reads are GET-only and limited to the services it reads. Apart from opening and closing its connection, the socket client refuses to send anything except subscribe, unsubscribe and `update-subscription` frames. When a model is read, every request is checked to carry no changes before it is sent. That holds for each import's saved mapping too, which is read from the import's own definition as Anaplan's import dialog reads it, and for each process's list of actions, read from the process's own definition as Anaplan's Actions tab reads it: the extension never saves a definition, and never asks Anaplan for a file's columns, a request that can store what it is given. Tests pin each of these rules.
- **Only when you ask.** The extension adds nothing to Anaplan's pages: no button and no panel. Nothing is read from Anaplan until you click the extension's icon in Chrome's toolbar. The results page that opens then starts the read. It reads again when you choose **Run again** or click the icon on that Anaplan tab. The icon brings an answering results tab and window forward and runs again there; a run already in progress carries on. A results page that is reloaded, duplicated, restored from history or reopened later reads nothing by itself: it shows the result its tab kept, if it kept one (see below), and waits for you to choose **Run again**, or **Run** when it has no result. Closing the results page stops the read. Clicking the icon on an Anaplan tab whose Cardigan script is gone, as after Cardigan was installed, updated or reloaded, puts the script back into that tab first (the **activeTab** and **scripting** permissions, neither with a warning): it reaches no other tab and no other site, and reads nothing until the results page asks. In the same way, where a model's page still holds the part of Cardigan that reads a model from an earlier version, the results page puts this version's into that tab: the same file Chrome puts there when the page loads, into the frames on that tab's own Anaplan host only. It reads nothing more for that. Where it cannot, it offers a button that refreshes the tab, and the tab is refreshed only when you choose it. The buttons under a row's name in its details, in a model's result, take that same Anaplan tab to the row's module or list in Model Building, or to the page of the model's settings that the row's table is on, and bring it to the front. Where that tab shows the model in Model Building, a module, a list or a page of the model's settings is opened inside the page: Cardigan's script in the model's frame asks the page's own Model Building client to open it, as that client's Modules list and General Lists do and as Model Building has it do when its sidebar opens a settings page, and Model Building shows it beside the tabs already open. Cardigan sends Anaplan nothing for it. If that tab has been closed, the first of them opens one tab in its place, and the others then use it. On the Overview, under **About this export**, the model's name takes that same tab to the model in Model Building: Cardigan's script in that tab is first asked which page the tab shows, which it says from the tab's address, and a tab that shows the model in Model Building already is only brought to the front. An app under **Apps** opens as an **App** button does. An app or a page built on the model opens in one more tab: the first **App** or **Page** opens a new tab next to the results page, and every later one takes that same tab to its address, so Cardigan opens at most one extra tab for apps and pages, and one in the place of a closed Anaplan tab. Cardigan changes which page a tab shows, and nothing in the model or the app.
- **Reading can load a model.** Reading a model's names, for an app or for the pages built on a model, subscribes to that model, which can make Anaplan load it, as opening one of its pages would.
- **A host is remembered while the tab is open.** Where Anaplan's model data service sends a model to another data centre's host, Cardigan's script in that Anaplan tab remembers the host, in memory, so that the next read of the model in that tab starts there. It is not stored anywhere, and it goes when the tab is closed or reloaded. In Model Building, the socket starts on the host the model's own page is served from, which is where the service would send it; where that host cannot be reached, it starts on the tab's, as before.
- **Three choices are kept.** The theme you chose with the sun or moon button, how you chose to group the Model map's modules, and whether the page shows its times in your time zone or in UTC are kept in the browser's local storage for the extension, so that the next results page opens with them. Each is one word, such as dark, role or utc, and holds nothing of your app or model. Your time zone itself is the browser's, which the page asks it for and keeps nowhere. They stay until the extension's storage is cleared.
- **The toolbar icon's menu.** Cardigan adds two items to the menu Chrome shows on its own toolbar icon (the **contextMenus** permission, which comes with no warning): **About Cardigan**, which opens Cardigan's About page in a new tab, and the version, greyed out, which does nothing. The icon's title says the version too. Nothing is added to any other menu or any page. The About page is part of the extension: it reads nothing from Anaplan and sends nothing, and its links to this project's pages on GitHub open only when you click them.
- **Nothing leaves the browser** except those reads to Anaplan, made with your own signed-in session. The results page and the About page are part of the extension and load nothing from the internet: the extension's content security policy lets its pages and its service worker load only files from its own package, and the packager refuses a policy that would allow more, or a manifest that declares none. The extension makes no file and offers no download: a result is shown on the results page and nowhere else, apart from the copy kept for a refresh (see below). There is no server, analytics or telemetry.
- **The model map is drawn in your browser.** It is made from the tables of a model's result and from nothing else: opening it reads nothing more from Anaplan and sends nothing anywhere.
- **The last result is kept for a refresh.** So that refreshing the results page does not lose it, the last result that finished in a results tab is kept in the browser's session storage for that tab. It is compressed with gzip and not encrypted, and it is kept with the time it was complete, the Anaplan tab's ID and the extension's version. A model's result read in Model Building holds where it was read as well: the site and the customer ID that tab's address named, by which the buttons in a row's details open its modules, apps and pages. It holds what the page shows: the details of your app or model. Beside it, the same storage keeps the IDs of the tabs the results page opened for apps and pages and in the place of a closed Anaplan tab, so that a refreshed page uses them again: only a tab the browser says the results page opened, so an ID the browser has since given to another tab, as after a restart, sends that tab nowhere. That storage is the extension's own, apart from every website's, and using it takes no permission. The result is not sent anywhere. The next result that finishes in that tab takes its place, and **Forget this result** on the Overview removes that tab's copy at once: the result stays on the page until the page is refreshed or closed, and a refresh then finds nothing kept. If the browser refuses the removal, the page says that the copy could not be removed and keeps the control, so that it can be tried again. A refreshed page shows only what its own version of the extension kept for the Anaplan tab named in its address. Anything else it finds there, and a kept value it cannot show, it removes, and then it waits for **Run**. Session storage is meant to go when its tab is closed, but that is the browser's to do, not the extension's: the browser may hold a closed tab's session data for a while, so that the tab can be reopened or a window restored, and a duplicated tab gets a copy. So closing the tab is no promise that the result is erased. A result too large to keep is not kept at all, and the page says so.
- **How a result was left is kept for a refresh.** Beside the kept result, the same session storage keeps, for that tab, how the result was left on the page, so that a refresh shows it so: each table's filters, as the values ticked or left out, which can be names and values from your app or model; its ranges, as typed, with the name of the time zone a range of days on a column of times was set in; the columns shown or hidden, the sort and the page, each column by its name; the rows a page lists; each table's search; how Where Used is listed; where the model map was, a group or a module by its name, which links it drew, the selected box, and the line item whose source inputs it showed, by its module's name and its own; and the details that were open, by their table, name and module or parent where needed. Edited formulas, counts and notes do not lose the selection; missing or ambiguous names leave it closed. It is plain text of a few thousand characters at most, kept with the kind and ID of the app or model it was made on, and sent nowhere. A new result for the same app or model keeps what still fits its tables; one for another app or model replaces it. **Forget this result** removes it with the result. If the storage refuses it, nothing is kept and the page works the same. As with the result, closing the tab is no promise that it is erased.

## Requests to Anaplan

Cardigan reads the engine from the export's Line Items columns, with no separate client cache read or request. Populated Cell Count or Calculation Complexity means Polaris; otherwise Classic. Both Classic and Polaris models are read in full through Model Building's Classic client. Only when no Classic frame answers within the wait does Cardigan use the partial reader without it, with the engine unknown. The Overview explains that read and its limits. A failed client read does not start another reader.

All of these are read-only, using your signed-in session. Braced words stand for the IDs in the app, model or page being read. No request goes to a Cardigan server, and Cardigan asks no AI model anything: from the Anaplan service named `llm-data-service` it only reads a Polaris model's metadata with the GETs listed below. The returned data stays in your browser.

### HTTP GETs

| Route | What Cardigan reads |
| --- | --- |
| `/a/springboard-definition-service/apps/{app}?includeUnpublished=true&includeReportPages=true` | The app and its page list, including unpublished entries so they can be identified. Only published page definitions are analysed. Also names apps for a model's page tables. |
| `/a/springboard-definition-service/boards/{page}` | A published board definition. |
| `/a/springboard-definition-service/grid-pages/{page}` | A published worksheet definition. |
| `/a/springboard-definition-service/reports/{page}` | A published report definition. |
| `/a/springboard-definition-service/customer/{customer}/model/{model}/pages` | The pages built on a model. |
| `/a/collaboration-actions-service/workspaces/{workspace}/models/{model}/imports` | Import names for page buttons and the Polaris import listing, including its type and source ID. |
| `/a/collaboration-actions-service/workspaces/{workspace}/models/{model}/exports` | Export names for page buttons and the Polaris export listing. |
| `/a/collaboration-actions-service/workspaces/{workspace}/models/{model}/processes` | Process names for page buttons and the Polaris process listing. No step definitions. |
| `/a/springboard-platform-gateway-service/customers/{customer}/workspaces/{workspace}/models/{model}` | Model and workspace names, only for a read without a Classic client. No engine fields are inspected. |
| `/a/springboard-platform-gateway-service/customers/{customer}/workspaces` | Workspace name, only when the model details did not supply it for a read without a Classic client. No engine fields are inspected. |
| `/a/llm-data-service/meta-data/workspace/{workspace}/model/{model}/modules` | Polaris module settings. |
| `/a/llm-data-service/meta-data/workspace/{workspace}/model/{model}/versions` | Polaris version names. |
| `/a/llm-data-service/meta-data/workspace/{workspace}/model/{model}/line-items/{module}` | Polaris line-item metadata, one request per module, at most four at once. |

These requests send `Accept: application/json`, `x-api-version: 1` (2 for the app definition), and `X-TracePath: springboard-ui`. Same-origin reads echo Anaplan's XSRF cookie in `X-XSRF-TOKEN`; cookies and tokens are not put in diagnostics. Reads to the model's Anaplan data-centre host use the signed-in session but do not forward that XSRF header. Action listings can fall back to the tab's host. The platform name and Polaris routes have narrow allowlists. No continuation URL from a Polaris response is followed.

### Model data socket

The socket connects to `wss://{Anaplan host}/a/springboard-widget-data-service/ws?tracePath=springboard-ui&clientVersion=page-analyzer&clientSessionId={session}`. It can follow the model data service to another allowed Anaplan host. Besides connection and disconnection, the only outgoing frames are `SUBSCRIBE`, `UNSUBSCRIBE` and `SEND` with `action-type: update-subscription`, which supplies read options for an existing subscription.

| Subscription destination | What it reads |
| --- | --- |
| `core://{workspace}:{model}` | Model status, waiting until it is available. This can cause Anaplan to load the model. |
| `core:/{workspace}:{model}/moduleViews` | Modules, saved views and available dimensions. The single slash is the service's route. |
| `core://{workspace}:{model}/lists` | List names and available list metadata. |
| `core://{workspace}:{model}/lists?subsets=true` | Names of additional dimensions and subsets. This does not establish per-list subset membership on Polaris. |
| `core://{workspace}:{model}/modules/{module}/lineItems` | Line-item names, IDs and formats for page references. Classic settings can supply these names without repeating every subscription. |
| `core://{workspace}:{model}/dimensions` | Dimensions of the requested modules. |
| `core://{workspace}:{model}/modules/{module}/dimensions/{dimension}` | Names of selected items used in page context or filter rules. |
| `core://{workspace}:{model}/applicableModules` | Modules that use a dimension, to find unnamed filter line items or dimensions. |
| `core://{workspace}:{model}/views/{view}` | Saved-view metadata: rows, columns and context selectors for app analysis. Model analysis does not request these layouts. |

No module cell-data view is subscribed to. The views subscription asks for metadata, not cell values.

### Classic model client

Through the client already loaded in the model's page, Cardigan asks for paged `MODEL_DEFINITION` grids: Line Items, Modules, General Lists, Line Item Subsets, the Line Item Subsets membership grid, Actions, Imports, Import Data Sources, Time Ranges, Versions, Source Models and Model Calendar. Actions is split into Processes, Imports, Exports and Other Actions; DCA is derived locally from the Line Items driver columns. Unused Line Items and Unused Modules are derived locally too, from those tables and the page definitions already read, with no further request. The client's existing cache supplies names, object types and calendar labels.

Three further definition grids supply every import's saved mapping, its data source's settings, and process actions in run order. These are reads of the stored definitions. Of a data source, Cardigan keeps only how uploaded data is read: encoding, separators, text delimiter, decimal separator, header row and first data row. Of a model source it keeps only whether the object is in this model, which places the import under In-Model Imports or Model-to-Model Imports; the object's ID only names its columns, and its model and workspace IDs are not kept. Cardigan never saves these definitions and never sends `GET_IMPORT_SOURCE_FIELDS`, `GET_IMPORT_SOURCE_ITEMS` or any other system action. Each client request is checked to reject submissions, system actions, model-summary fetches or any request type other than a view request. The client's transport sends the read; this is separate from Cardigan's GET-only REST helper.

Opening a module, list or settings page uses the Model Building client's navigation where available, or changes a tab's address. It makes no edit and runs no model action. The Model map is built locally and makes none of these requests.
